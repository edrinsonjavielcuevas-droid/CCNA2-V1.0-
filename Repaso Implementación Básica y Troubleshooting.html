Repaso: Implementación Básica y Troubleshooting

Este documento consolida los conceptos críticos aplicados en el laboratorio de configuración inicial de dispositivos Cisco, enfocado en las trampas más comunes y las mejores prácticas.

01. La Capa Física y "El Factor Packet Tracer"

Precisión de Nomenclatura: En simuladores (y en la automatización real), la sintaxis es ley. El Display Name (ej. PC-1) no es un simple detalle visual; si las instrucciones incluyen un guion, omitirlo invalida toda la configuración frente al script de evaluación.
Selección de Medios (Cables):
  • Directo (Straight-Through): Se usa para conectar dispositivos que operan en diferentes capas del modelo OSI (ej. Router a Switch, PC a Switch).
  • Cruzado (Crossover): Se usa para dispositivos similares (Switch a Switch, Router a Router). Aunque el Auto-MDIX lo resuelve en la vida real, los simuladores y certificaciones evalúan la teoría estricta.

02. Acceso Remoto Seguro (El fin de Telnet)

La administración de dispositivos fuera de la ubicación física requiere protocolos seguros.

Vulnerabilidad de Telnet: Opera en el puerto TCP 23. Es obsoleto porque transmite toda la sesión (incluyendo contraseñas) en texto plano, haciéndolo vulnerable a analizadores como Wireshark.
Implementación de SSH: Opera en el puerto TCP 22. Cifra la autenticación y todo el tráfico.
ip domain-name [dominio.com] crypto key generate rsa username [usuario] secret [pass]
Comandos críticos para habilitar SSH.

Nota: Al generar la llave RSA, se recomiendan 1024 bits.
line vty 0 15 transport input ssh login local
Asegurar líneas VTY (0 a 15 en switches).

transport input ssh obliga a usar solo SSH.
login local obliga a consultar la base de datos local de usuarios.

03. Direccionamiento e Interfaces

Routers: Tienen la función de interconectar diferentes redes. Sus interfaces físicas tienen características específicas:
  • Vienen inhabilitadas por defecto (shutdown). Siempre requieren no shutdown.
  • Requieren obligatoriamente direccionamiento IP para operar (ip address X.X.X.X Y.Y.Y.Y).
  • Buena práctica: Usar description en cada puerto para agilizar el troubleshooting futuro.
Switches y la SVI: Los switches operan en Capa 2, pero para administrarlos por red (Capa 3), requieren una Interfaz Virtual de Switch (SVI).
  • Default Gateway: Al igual que una PC, si el switch necesita ser administrado desde una red diferente (por ejemplo, por un administrador en otra ciudad), necesita conocer la puerta de enlace predeterminada (ip default-gateway [IP_del_Router]).
interface vlan 1 ip address [IP] [Máscara] no shutdown
Configuración de SVI: Se configura asignando una IP a la VLAN de administración.

04. Interfaces de Bucle Invertido (Loopback)

Conceptos Clave:
  • Concepto: Son interfaces 100% lógicas (software) internas del router.
  • Comportamiento: Al no depender de hardware, su estado siempre es Up (activo) mientras el sistema operativo funcione.
  • Utilidad: Fundamentales para mantener la estabilidad en procesos de enrutamiento interno, pruebas continuas y simulación de redes adicionales en entornos de laboratorio sin necesidad de hardware extra.
interface loopback 0 ip address 1.1.1.1 255.255.255.255
Creación y asignación de IP a una interfaz lógica de Loopback.

05. Auditoría Rápida de Estados

Los tres comandos salvavidas para el troubleshooting de interfaces:

show ip interface brief
Mapeo rápido de IPs y estados (Up/Down).
show running-config interface [id]
Aísla la configuración de un puerto específico.
show ip route
Verifica si la red conectada ya fue inyectada exitosamente a la tabla de enrutamiento (códigos 'C' y 'L').
