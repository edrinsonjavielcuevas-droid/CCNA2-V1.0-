Configuración Básica, Seguridad, IPv4, IPv6 y SSH en Routers Cisco

Guía de estudio estructurada para CCNA. Dominio de conceptos, sintaxis y troubleshooting.

1. Fundamentos de configuración

El sistema operativo Cisco IOS utiliza una estructura jerárquica. No puedes ejecutar comandos avanzados si no estás en el nivel (modo) correcto.

Modo Prompt Comando para entrar Para qué sirve
EXEC de usuario Router> (Modo por defecto al conectar) Verificación muy básica. Comandos limitados (ping, telnet).
EXEC privilegiado Router# enable Acceso total a todos los comandos show, depuración y guardado.
Config. Global Router(config)# configure terminal Realizar cambios que afectan al dispositivo en su totalidad (hostname, contraseñas).
Config. de Interfaz Router(config-if)# interface g0/0/0 Configurar parámetros de un puerto específico (IPs, estado).
Config. de Línea Router(config-line)# line vty 0 4 Configurar accesos administrativos (consola, SSH, Telnet).
Comandos Clave de Navegación

exit: Retrocede un nivel en la jerarquía (ej. de config-if a config).

end (o Ctrl+Z): Salta directamente al modo EXEC privilegiado (#) sin importar en qué subnivel estés.

2. Identidad básica del router

Antes de asegurar un router, debemos darle una identidad en la red.

Hostname (Nombre de host)
Router(config)# hostname R1

Qué hace: Cambia el nombre lógico del dispositivo. El prompt cambiará inmediatamente de Router(config)# a R1(config)#.

Importancia: Crítico para administración. Si gestionas 50 routers y todos se llaman "Router", es fácil aplicar configuraciones en el dispositivo equivocado.

Nombre de Dominio
R1(config)# ip domain-name ccna-lab.com

Para qué sirve: Define el dominio DNS al que pertenece el router.

Relación con SSH: Para habilitar SSH, el router debe generar claves RSA. El router combina su Hostname + Nombre de Dominio (ej. R1.ccna-lab.com) para crear la identidad única de estas claves criptográficas. Por eso, siempre debe configurarse el dominio antes de generar las claves.

3. Seguridad de contraseñas

Cifrado general de contraseñas
R1(config)# service password-encryption

Qué protege: Por defecto, comandos como password cisco (usado en consola o VTY) se guardan en texto claro. Este comando aplica un cifrado débil (Tipo 7) a todas las contraseñas en el archivo de configuración para evitar que alguien que mire tu pantalla por encima del hombro las lea.

Limitación: Es fácilmente reversible (crackeable) en segundos en internet. Protege contra observadores casuales, no contra hackers.

Longitud Mínima
R1(config)# security passwords min-length 12

Qué significa: Obliga a que cualquier nueva contraseña que se configure a partir de este momento tenga al menos 12 caracteres.

Si intentas poner una más corta: El router rechazará el comando lanzando un error (Password too short).

Enable Secret vs Enable Password
R1(config)# enable secret P@ssw0rd2024

Protege el paso del modo usuario (>) al privilegiado (#).

  • enable password: Se almacena en texto claro (a menos que uses service password-encryption, e incluso así es tipo 7, débil).
  • enable secret: Utiliza un algoritmo Hash robusto (Tipo 5 / MD5 o superior). Debe preferirse siempre. Si configuras ambos, el router solo te pedirá el secret.

4. Usuarios locales

R1(config)# username SSHadmin secret 55Hadm!n2020

Desglose del comando:

  • username: Crea una entrada en la base de datos local del router.
  • SSHadmin: El nombre de la cuenta.
  • secret: Indica que la contraseña se almacenará con un hash fuerte (Tipo 5), en lugar de texto claro (que sería si usaramos la palabra password en su lugar).
  • 55Hadm!n2020: La credencial asignada. Nota: Jamás uses tus contraseñas personales o de producción en entornos de Packet Tracer.

5. Configuración de la consola

Asegura el puerto físico (cable celeste) del router.

R1(config)# line console 0
R1(config-line)# password C0ns0l@P@ss
R1(config-line)# exec-timeout 4 0
R1(config-line)# login
R1(config-line)# exit
  • line console 0: Entra a configurar el único puerto de consola físico (el número 0).
  • password <pass>: Define la contraseña para este puerto.
  • exec-timeout 4 0: Desconecta la sesión automáticamente tras 4 minutos y 0 segundos de inactividad (sin presionar teclas). Evita que un administrador deje su sesión abierta por accidente.
  • login: Obliga al puerto a solicitar la contraseña previamente configurada. Sin esto, la contraseña existe pero no se pide.

6. Configuración de VTY (Virtual Teletype)

Las líneas VTY son puertos lógicos usados para la administración remota (vía red, no por cable físico). Por defecto los routers tienen 5 líneas VTY concurrentes (0, 1, 2, 3 y 4).

R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
R1(config-line)# exec-timeout 4 0
R1(config-line)# exit

login local vs login:

  • login: Pide únicamente la contraseña global de la línea VTY.
  • login local: Pide Usuario y Contraseña y los verifica contra la base de datos local del router (creada con el comando username en el paso 4).

transport input ssh: Ordena a las líneas VTY que solo acepten conexiones SSH, bloqueando protocolos inseguros como Telnet.

TelnetSSH (Secure Shell)
Sin cifrado (Texto plano)Comunicación 100% cifrada
Más inseguroMás seguro
Credenciales fácilmente expuestas (Wireshark)Credenciales y datos protegidos por túnel RSA

7. SSH: Proceso Completo

SSH requiere varios elementos trabajando juntos para crear el túnel seguro.

R1(config)# ip domain-name ccna-lab.com
R1(config)# username SSHadmin secret 55Hadm!n2020
R1(config)# crypto key generate rsa modulus 1024
R1(config)# line vty 0 4
R1(config-line)# login local
R1(config-line)# transport input ssh
  • Claves RSA: Son el par de llaves (Pública y Privada) necesarias para el cifrado asimétrico.
  • Modulus 1024: Define la longitud de la clave en bits. 1024 es el mínimo aceptable para SSH versión 2 en routers modernos (aunque 2048 es más seguro en el mundo real).
PC-A (Cliente SSH) ↔ [Túnel Cifrado RSA 1024] ↔ R1 (Valida 'SSHadmin' vía 'login local')

8. Banner de seguridad (MOTD)

R1(config)# banner motd #ACCESO NO AUTORIZADO ESTRICTAMENTE PROHIBIDO#

MOTD (Message Of The Day): Es un texto legal que aparece justo antes de la solicitud de contraseña (tanto en consola como por red).

Para qué se utiliza: Sirve como advertencia legal. Si no adviertes que el sistema es privado, en algunas jurisdicciones los intrusos podrían alegar que no sabían que el acceso estaba restringido. Los caracteres # actúan como delimitadores de inicio y fin del mensaje.

9. Bloqueo por intentos fallidos

Protege contra ataques de fuerza bruta intentando adivinar contraseñas repetidamente.

R1(config)# login block-for 120 attempts 3 within 60

Desglose lógico:

  • attempts 3: Si hay 3 intentos fallidos...
  • within 60: ...dentro de una ventana de 60 segundos...
  • block-for 120: ...el router bloquea nuevos inicios de sesión durante 120 segundos (2 minutos).
Fallo → Fallo → Fallo (en menos de 1 min) 🛑 ACCESO BLOQUEADO POR 2 MINUTOS

10. Configuración IPv4

R1(config)# interface g0/0/0
R1(config-if)# ip address 192.168.0.1 255.255.255.0
R1(config-if)# no shutdown

El comando vincula una Dirección IP y su Máscara de Subred al puerto físico. Esta IP se convertirá en el Default Gateway (Puerta de enlace) de los hosts (PCs, Servidores) conectados a esa red LAN específica.

11. Configuración IPv6

R1(config)# ipv6 unicast-routing

Este comando global es obligatorio. Sin él, el router puede tener IPs IPv6, pero no reenviará (enrutará) paquetes IPv6 entre redes.

R1(config)# interface g0/0/0
R1(config-if)# ipv6 address 2001:db8:acad::1/64
R1(config-if)# ipv6 address fe80::1 link-local
R1(config-if)# no shutdown
  • IPv6 Global Unicast (2001:.../64): Es la dirección enrutable públicamente (similar a la IP pública en IPv4, aunque en IPv6 se da a cada host). El /64 es la longitud del prefijo (similar a la máscara).
  • IPv6 Link-Local (fe80::1): Dirección exclusiva de red local. No atraviesa routers. Los hosts la usan para comunicarse con su gateway.
  • ¿Por qué fe80::1 se puede repetir en varias interfaces? Como el tráfico Link-Local nunca sale del enlace físico local (broadcast domain), no hay conflicto de enrutamiento si la G0/0/0 y la G0/0/1 usan la misma IP fe80::1, ya que son redes aisladas en Capa 2.

12. Interfaz Loopback

R1(config)# interface loopback0
R1(config-if)# ip address 10.0.0.1 255.255.255.0
R1(config-if)# ipv6 address 2001:db8:acad:2::1/64
R1(config-if)# ipv6 address fe80::1 link-local

Qué es: Una interfaz 100% lógica (software). No existe físicamente (no puedes conectar un cable).

Diferencia: Una interfaz física puede caerse (estado down) si el cable se desconecta. La Loopback siempre está UP a menos que el router entero se apague o un administrador le dé shutdown.

Utilidad: Es ideal para administración remota (SSH a la loopback garantiza que si un puerto físico cae, aún puedes entrar por otro camino) y para simular redes adicionales en laboratorios.

13. Descripciones de Interfaces

R1(config-if)# description Connection to Server

No altera en absoluto el funcionamiento de la red. Es puramente documental. Acelera el troubleshooting meses después cuando ejecutas show running-config y necesitas saber a dónde va conectado ese puerto sin ir a seguir el cable físico.

14. Activación de Interfaces

R1(config-if)# no shutdown

Los puertos en un router Cisco vienen apagados de fábrica por seguridad.

  • administratively down: Significa que un administrador emitió explícitamente el comando shutdown (o viene así por defecto).
  • up / up: El primer "up" significa que la Capa 1 (física/cable) funciona. El segundo "up" significa que la Capa 2 (protocolo de línea/enlace de datos) está operando correctamente.

16. Rutas directamente conectadas

R1# show ip route

Este comando muestra la tabla de enrutamiento (el "mapa" del router).

  • C = Connected: Representa la red base (ej. 192.168.0.0/24) que se inyecta automáticamente cuando configuras una IP y levantas la interfaz.
  • L = Local: Representa la IP exacta (host) asignada al propio router (ej. 192.168.0.1/32).

Basado en nuestra tabla, veríamos 3 rutas con código C (192.168.0.0, 192.168.1.0 y 10.0.0.0) porque tenemos 3 interfaces activas.

17. COMANDOS SHOW QUE DEBO DOMINAR

  • show running-config: Muestra TODA la configuración activa en la memoria RAM. Úsalo para validar lo que acabas de teclear.
  • show startup-config: Muestra la configuración guardada en la NVRAM (lo que cargará si se apaga).
  • show version: Muestra versión de IOS, modelo, tiempo encendido y registro de configuración (0x2102).
  • show ip interface brief: El salvavidas. Resumen rápido tabular de IPs asignadas y estados (up/down). Ayuda a detectar puertos apagados.
  • show ipv6 interface brief: Igual al anterior, pero para IPv6. Útil para validar que la Link-Local y Global Unicast se aplicaron.
  • show ip route / show ipv6 route: Muestra la tabla de enrutamiento. Verifica si el router sabe cómo llegar a otras redes.
  • show interfaces: Datos masivos y detallados de Capa 1 y 2 (MAC, errores CRC, drops, ancho de banda).
  • show ip interface: Datos detallados de Capa 3 (Verificar la máscara de subred aplicada, ACLs entrantes/salientes).

18. El poder del Pipe (|)

El símbolo | permite filtrar resultados inmensos en el router.

include show running-config | include domain

Muestra únicamente las líneas individuales que contienen la palabra "domain". Evita leer 3 páginas buscando si el dominio se configuró.

section show running-config | section vty

Muestra el bloque completo de configuración que coincide (la línea coincidente y todo lo anidado debajo de ella, como passwords, timeout, etc).

19. Running-config vs Startup-config

[RAM Volátil] Running-config
↓
copy running-config startup-config
↓
[NVRAM Permanente] Startup-config

¿Qué ocurre si reinicio el router antes de guardar?
Cualquier comando que escribiste se pierde para siempre. El router arrancará con la última configuración guardada (startup-config) o en blanco.

20. Reloj del Router

R1# clock set 14:30:00 13 Aug 2026

Ajusta el reloj de hardware temporalmente. (Requiere modo EXEC privilegiado #, no modo de configuración global). Vital para que los logs (registros de errores) tengan marcas de tiempo reales que faciliten auditorías.

21. Verificación de Conectividad

  • Ping IPv4: ping 192.168.0.10
  • Ping IPv6: ping 2001:db8:acad::10

Para verificar SSH: Desde el terminal de PC-A usamos el comando ssh -l SSHadmin 10.0.0.1. (Regla de oro: Antes de intentar SSH, ¡haz un ping! Si no hay conectividad IP básica, SSH jamás conectará).

22. Registro de configuración 0x2142

R1# show version | include register

El valor normal es 0x2102 (Carga normal).
¿Qué ocurre si el registro es 0x2142? El router ignora deliberadamente el archivo startup-config durante el arranque y sube en blanco. Es la técnica oficial de Cisco para recuperación de contraseñas, permitiéndote entrar si olvidaste el 'enable secret'.

23. Seguridad de Telnet

Telnet transmite datos en texto claro. Si un atacante ejecuta un sniffer de red (Wireshark) entre tu PC y el router, verá exactamente qué usuario y qué contraseña tecleaste para entrar. Por ello siempre usamos transport input ssh, que encapsula todo el tráfico.

24. Diagnóstico de Interfaces

Al hacer un show ip int brief puedes ver:

  • up / up: Todo perfecto. Capa física y enlace de datos operando.
  • administratively down: Olvidaste hacer no shutdown.
  • down / down: Fallo físico (cable desconectado, equipo al otro extremo apagado, cable dañado).

¿Crees que te equivocaste de máscara (/24 vs /8)? show ip int brief NO te muestra la máscara. Debes usar show ip interface g0/0/0 o show running-config interface g0/0/0 para ver el detalle exacto.

25. ERRORES QUE PUEDEN HACER FALLAR EL LAB

  • Error de Sintaxis Oculto: Escribir transpor input ssh. El router lanza un error por la "t" faltante y rechaza la orden. Luego crees que habilitaste SSH, pero no fue así.
  • Interfaz Incorrecta: Tratar de entrar a interface g0/0 cuando el modelo de router usa nomenclatura de 3 dígitos interface g0/0/0.
  • Rigidez de Packet Tracer: PT califica scripts. Si el lab pide descripción Connection to Server y tú escribes connection to server (minúscula), el motor te restará puntos.
