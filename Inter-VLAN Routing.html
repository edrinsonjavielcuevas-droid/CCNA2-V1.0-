Guía Definitiva: Inter-VLAN Routing

Explicado paso a paso para principiantes, desde los conceptos básicos hasta la resolución de problemas.

1. ¿Qué es el Routing entre VLAN y por qué lo necesitamos?

Para entender este tema, primero debemos comprender el problema: los hosts de una VLAN no pueden comunicarse con los hosts de otra VLAN a menos que haya un router o un switch de capa 3 para proporcionar servicios de enrutamiento[cite: 1].

Aquí es donde entra nuestra solución: Inter-VLAN routing. Este es el proceso de reenviar el tráfico de red de una VLAN a otra VLAN[cite: 1].

Las Tres Opciones de Enrutamiento

Históricamente, han existido tres formas principales de lograr esto. Tres opciones incluyen heredado, router-on-a-stick y switch de capa 3 con SVIs[cite: 1]:

  • 1. Enrutamiento Heredado (Legacy): Utiliza un router con múltiples interfaces Ethernet[cite: 1]. En este modelo, cada interfaz del router estaba conectada a un puerto del switch en diferentes VLAN[cite: 1]. Sin embargo, requerir una interfaz física del router por VLAN agota rápidamente la capacidad de la interfaz física del router[cite: 1].
  • 2. Router-on-a-stick: El método 'router-on-a-stick' inter-VLAN routing solo requiere una interfaz Ethernet física para enrutar el tráfico entre varias VLAN de una red[cite: 1]. La interfaz Ethernet del router Cisco IOS se configura como un troncal 802.1Q y se conecta a un puerto troncal en un switch de capa 2[cite: 1].
  • 3. Switch de Capa 3 (El método moderno): El método moderno es el enrutamiento entre VLAN en un switch de capa 3 mediante SVIs[cite: 1]. Una SVI (Interfaz Virtual de Switch) se crea para una VLAN que existe en el switch[cite: 1]. El SVI realiza las mismas funciones para la VLAN que una interfaz del router[cite: 1]. Proporciona procesamiento de capa 3 para los paquetes que se envían ao desde todos los puertos de conmutador asociados con esa VLAN[cite: 1].

2. Configuración de Router-on-a-stick

Para configurar un switch con VLAN y enlaces troncales, realice los siguientes pasos: cree y asigne un nombre a las VLAN, cree la interfaz de administración, configure los puertos de acceso y configure los puertos de enlace troncal[cite: 1].

💡 Concepto Clave: Subinterfaces

Como solo usamos un cable físico en este método, dividimos ese puerto en varios puertos virtuales o "subinterfaces". La interfaz del router se configura mediante subinterfaces para identificar VLAN enrutables[cite: 1]. Las subinterfaces son interfaces virtuales basadas en software, asociadas con una única interfaz física[cite: 1].

Pasos de Configuración en el Router:

  • Para el método de router-on-a-stick, se requieren subinterfaces configuradas para cada VLAN que se pueda enrutar[cite: 1].
  • Se crea una subinterfaz mediante el comando interface interface_id subinterface_id global configuration mode[cite: 1].
  • Es necesario asignar una dirección IP a cada subinterfaz del router en una subred única para que se produzca el routing[cite: 1].
  • Cuando se han creado todas las subinterfaces, la interfaz física debe habilitarse mediante el comando de configuración de no shutdown interfaz[cite: 1].

Verificación de Router-on-a-stick:

  • Desde un host, compruebe la conectividad con un host de otra VLAN mediante el ping comando[cite: 1].
  • ping Utilícelo para verificar la conectividad con el host y el switch[cite: 1].
  • Para verificar y solucionar problemas utilice los comandos, show ip route, show ip interface brief, show interfaces y show interfaces trunk[cite: 1].

3. Enrutamiento usando Switches de Capa 3

En redes grandes y modernas, dependemos de los switches multicapa. Las LAN de campus empresariales utilizan switches de capa 3 para proporcionar enrutamiento entre VLAN[cite: 1].

¿Por qué? Porque los switches de capa 3 utilizan switching basado en hardware para lograr velocidades de procesamiento de paquetes más altas que los routers[cite: 1].

Capacidades y Configuración (SVI):

  • Las capacidades de un switch de Capa 3 incluyen el enrutamiento de una VLAN a otra utilizando múltiples interfaces virtuales conmutadas (SVI) y la conversión de un puerto de switch de Capa 2 a una interfaz de Capa 3 (es decir, un puerto enrutado)[cite: 1].
  • Para proporcionar enrutamiento entre VLAN, los switches de capa 3 utilizan SVIs[cite: 1].
  • Los SVIs se configuran utilizando el mismo comando interface vlan vlan-id utilizado para crear el SVI de administración en un switch de capa 2[cite: 1].
  • Se debe crear un SVI de Capa 3 para cada una de las VLAN enrutables[cite: 1].
  • Para configurar un switch con VLAN y trunking, siga los pasos siguientes: cree las VLAN, cree las interfaces VLAN SVI, configure los puertos de acceso y habilite el enrutamiento IP[cite: 1].
  • Desde un host, compruebe la conectividad con un host de otra VLAN mediante el ping comando[cite: 1]. A continuación, compruebe la conectividad con el host mediante el comando host de ping Windows[cite: 1].
  • Las VLAN deben anunciarse mediante enrutamiento estático o dinámico[cite: 1].

Puertos Enrutados (Routed Ports):

  • Para habilitar el enrutamiento en un switch de capa 3, se debe configurar un puerto enrutado[cite: 1].
  • Un puerto enrutado se crea en un switch de Capa 3 deshabilitando la función switchport de un switch de Capa 2 que está conectado a otro dispositivo de Capa 3[cite: 1].
  • La interfaz se puede configurar con una configuración IPv4 para conectarse a un router u otro switch de capa 3[cite: 1].
  • Para configurar un switch de capa 3 para enrutar con un router, siga estos pasos: configure el puerto enrutado, habilite el enrutamiento, configure el enrutamiento, verifique el enrutamiento y verifique la conectividad[cite: 1].

4. Resolución de Problemas (Troubleshooting)

Hay varias razones por las que una configuración entre van puede no funcionar[cite: 1]. Todos están relacionados con problemas de conectividad, como las VLAN faltantes, los problemas del puerto troncal del switch, los problemas del puerto de acceso del switch y los problemas de configuración del router[cite: 1].

Causas Comunes de Fallas:

  • VLAN Faltantes: Podría faltar una VLAN si no se creó, se eliminó accidentalmente o no se permite en el enlace troncal[cite: 1].
  • Errores de Asignación (Heredado): Otro problema para el enrutamiento entre VLAN incluye puertos de switch mal configurados[cite: 1]. En una solución interVLAN heredada, podría producirse un puerto de switch mal configurado cuando el puerto del router de conexión no está asignado a la VLAN correcta[cite: 1].
  • Errores de Enlace Troncal (Router-on-a-stick): Con una solución router-on-a-stick, la causa más común es un puerto troncal mal configurado[cite: 1].
  • Errores de Subinterfaz: Los problemas de configuración del router con configuraciones de router-on-a-stick suelen estar relacionados con configuraciones erróneas de subinterfaz[cite: 1].

Herramientas de Diagnóstico:

  • Cuando se sospecha un problema con una configuración del puerto de acceso del switch, utilice los ping comandos show interfaces interface-id switchport y _interface- para identificar el problema[cite: 1].
  • Verificar el estatus de las interfaces usando el show ip interface brief comando[cite: 1].
